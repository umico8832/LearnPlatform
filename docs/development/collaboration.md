# Claude 与 Codex 协作

本文档维护 Claude 与 Codex 在本项目的分工、任务单、代码与环境约定、阶段节奏和 Codex 的调用方式。
开发循环与完成标准见[开发工作流](workflow.md)，分支与历史操作见 [Git 规则](git-rules.md)，
验证范围见[测试策略](testing.md)。

## 分工

- Claude 和 Codex 地位平等，按专长分工，像前端和后端程序员。Claude 负责前端：界面、交互、动画动效、
  每类页面的第一版和设计规则。Codex 负责后端与其余工程：后端与数据、算法、接口文档、CI、工具脚本、
  测试基础设施、查资料与核对事实、截图初筛、冷读挑错、内容初稿、备选标题。
- 不需要 Claude 专长的活交给 Codex：摸清后端、数据和其他非前端的现有实现，排查 CI、E2E 与环境问题，
  [完整检查](testing.md#完整检查整个任务做完时)，批量截图与初筛，文档同步与冷读，以及前端里不讲究审美的活
  （测试、照已定样式迁移同类页面、接口接线）。读一两个文件、跑一个聚焦测试这类小事 Claude 自己做；
  做着发现要反复试或越做越大，就停手转交。
- Codex 做前端的活时按 Claude 已定的设计做，不改视觉与交互取舍；交回后 Claude 看效果。
- 谁做的谁负责到底：自己实现，自己跑聚焦验证，按 Git 规则提交；完整检查交给 Codex，失败归谁的改动谁修。
  各自专长范围内的取舍由负责的一方决定。不设常规的互相审批，只在对方专长能补上或风险高时请对方看一眼。
- 教学内容的写审分离、证据记录与发布门禁见[教学内容审核](../product/explanation-conventions.md#教学内容审核)；
  其中的页面检查由 Claude 负责。

## 任务单

- 默认从 Claude 进；纯后端的活用户也可以直接找 Codex。不论从哪进，需求和进度都记在任务单：
  主检出（`/Users/umico/Documents/LearnPlatform`）的 `tmp/backlog.md`，不入库，两边用绝对路径读写。
- 每条写明归谁和完成标准。前端需要后端支持时，Claude 在条目里写清前端需要什么，不为此去读后端代码。
- 两边都可以新增条目，在对方范围里发现的问题写成归对方的新条目；已有条目只由负责的一方改，
  做完改为 `[x]` 并附提交号。遇到要对方或用户拍板的问题，写进“待讨论”，跳过做下一条，不停下也不自己猜。
- 具体任务只在任务单里维护；[项目状态](../project/status.md)只写阶段级的下一步。

## 代码与环境

- 接口归后端：Codex 先把契约写进 [API 参考](../reference/api/index.md)再实现，Claude 按契约做页面。
- Codex 写代码时在自己的 worktree 和分支上：`git worktree add ~/.worktrees/LearnPlatform/<task> -b codex/<task> main`，
  不在 `~/Documents` 下另建目录。同时跑的 Codex 任务不写同一个目录。验证、截图这类只读任务可以在 Claude 的检出里跑，
  但不改任何文件（不加 `--fix`、不更新快照）。
- 合回 `main` 按 [Git 规则](git-rules.md#5-revert检查点分支与推送)中 Codex 分支的长期授权进行；前后端接通前先合入。
- Codex 用 Testcontainers 和[隔离 E2E](testing.md#8-浏览器-e2e-环境) 验证；日常开发的后端只从主检出起。
  同一时间只跑一套 E2E 环境。

## 阶段节奏

- 开头：Claude 跟用户定范围，在任务单写下前端条目和后端需求，启动 Codex。
- 中间：分头做。接通后 Claude 在浏览器走一遍主流程，后端问题写回任务单。
- 收尾：Codex 冷读文档，看一遍待推送的提交，只报告拆分和事实问题，由作者改。
  需要改历史的，Git 规则已授权的 fixup 直接做，推送时列出；其余的在用户要求推送时一并问。推送只在用户要求时做，
  推送前的检查见 Git 规则；推送后 CI 由 Codex 按[推送后 CI 失败](workflow.md#推送后-ci-失败)看证据并修复。
- 产品方向、范围变化、推送、删除数据由用户决定；需要用户拍板的事由正在跟用户对话的一方汇总。

## 调用 Codex

- 本项目在全局调用命令上加 `-m gpt-6.1-sol -c model_reasoning_effort="high"`；难排查的 bug、算法设计、
  反复失败的问题改用 `xhigh`。
- 日常跑法：一次交一个具体任务。阶段跑法：按任务单跑完当前阶段归 Codex 的条目就停。都不开无止境的循环；
  任务单里没有归 Codex 的条目时就停，不找事做。
