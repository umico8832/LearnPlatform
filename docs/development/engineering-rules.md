# 工程规则

本文档为 LearnPlatform 的工程判断辅助清单，用于新增功能、修复问题、重构或判断代码归属时参考。它不替代 `docs/architecture/overview.md`、`docs/reference/api/index.md`、`docs/reference/database/index.md` 和 `docs/development/testing.md`。

---

## 1. 改动范围

- 默认采用工程保守模式：小步修改，聚焦当前目标，不做无关重构。
- 最小改动不等于持续往大文件、大类、大组件里堆代码；新增独立功能时应考虑合理归属。
- 如果发现现有模式不佳，可以记录建议或在总结中说明，不要顺手做大范围结构调整。
- 结构整理应单独成轮，不要和功能开发、Bug 修复混在一起。

---

## 2. 后端归属

后端应尽量遵循项目现有分层：

- Controller 负责请求入口、权限边界、参数接收和响应封装；
- Service 负责业务规则、事务边界和跨 Mapper 协作；
- Mapper 负责数据访问；
- DTO / VO 负责请求和响应数据结构；
- Entity 映射数据库表；
- Config / Security 负责配置、安全、过滤器等基础设施。

涉及判分、考试、权限、限流、AI 调用、缓存、文件上传、数据库一致性、事务或安全的改动时，需要更谨慎地确认业务约束，不能为了测试通过而弱化规则。

---

## 3. 前端归属

前端应尽量遵循项目现有分层：

- `views/` 放页面级视图；
- `components/` 放可复用组件；
- `api/` 放接口请求封装；
- `stores/` 放跨页面状态；
- `router/` 放路由和守卫；
- `utils/` 放通用工具函数；
- `types/` 放 TypeScript 类型。

复杂页面不要无限膨胀。出现多个页面复用的展示、表单、状态转换或数据格式化逻辑时，应考虑抽到合适的组件、工具或类型文件中。

---

## 4. 业务与质量底线

- 不用伪实现冒充完成功能。
- 不把临时代码写成长期方案。
- 不用硬编码绕过权限、状态、判分、配额、缓存或数据一致性规则。
- 不为了让测试通过而降低真实业务约束。
- 前后端字段和枚举含义应保持一致。
- 新增依赖要说明原因，并优先使用项目已有技术栈和模式。
- 数据库字段命名使用 `snake_case`，Java / TypeScript 字段命名保持项目现有风格。
- 涉及真实密钥、Token、Cookie、数据库密码和个人隐私数据时，遵守 `AGENTS.md` 的安全底线。

---

## 5. 敏感模块

以下模块改动需要额外谨慎，优先补充必要验证：

- AI 调用、流式输出、配额和调用日志；
- 统计、缓存、学习报告和图表数据；
- 考试、判分、错题归集、练习记录；
- 用户鉴权、角色权限、登录限流和验证码；
- 数据库迁移、逻辑删除、唯一约束和事务；
- 文件上传、导入导出；
- Docker、部署、监控、日志和 CI。

---

## 6. 测试与文档

- 行为改动按 `docs/development/workflow.md` 执行任务契约、Red-Green-Refactor、验证和交付流程。
- 是否补测试按 `docs/development/testing.md` 判断，不追求数量，优先保护高风险业务。
- 接口变化同步 `docs/reference/api/` 中对应领域文档。
- 数据库变化同步 `docs/reference/database/` 中对应领域文档。
- 架构或目录边界变化同步 `docs/architecture/overview.md`。
- 每轮开发记录追加到 `docs/project/changelog/` 的当前月份文件；月份变化时同步更新索引。
