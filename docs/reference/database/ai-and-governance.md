# AI 与治理数据

## 调用与配额

| 表 | 首次迁移 | 职责 | 关键约束 |
|---|---|---|---|
| `ai_call_log` | V1，后续迁移扩展 | 功能、模型、Token、成本、trace 和指纹 | 不保存 API Key；成本按调用时配置固化 |
| `ai_quota_audit_log` | V12 | 用户配额调整审计 | 保存操作者、前后值和原因 |
| `ai_usage_alert` | V14 | 用量异常和运营提醒 | 确认操作保留确认人和时间 |

调用准入在独立短事务内锁定用户并插入 `RUNNING` 日志，结束后更新原记录。`call_id` 唯一，
`run_id` 对普通调用为空；`call_kind` 区分聊天与后续 Embedding。`requested_model` 保存请求模型，
`model` 使用上游返回名称（若提供），价格在准入时快照。`finish_reason` 与 `outcome` 区分生成结束与处理结果。

`status` 保留旧的成功标识，未确认记录依靠 `outcome=RUNNING` 识别。配额计入全部已登记调用，
完成日志列表、成功率和运营报告排除未确认记录。旧日志的新增追踪字段保持空值，不编造历史元数据。

上游失败或后端结构校验失败仍可能有真实用量；缺失字段保持空值。进程退出或审计更新失败时，
已提交登记不随领域事务回滚；需核对上游及运行记录后处理未确认状态，不自动返还配额。

## Tutor Agent 运行

| 表 | 首次迁移 | 职责 | 关键约束 |
|---|---|---|---|
| `tutor_agent_run` | V95 | 运行归属、状态和下一消息序号 | `run_key` 唯一；同一运行通过状态条件更新避免并发推进 |
| `tutor_agent_message` | V95 | 成功轮次的用户可见问题与回答 | `(run_id, sequence_no)` 唯一；内部工具消息不持久化 |

一次用户提问中的多次 `ai_call_log` 共享 `tutor_agent_run.run_key` 对应的 `run_id`，但各自独立准入、计费和
记录终止原因。调用审计仍不保存 Prompt 或响应正文；可恢复对话正文属于独立的用户功能数据，只在最终回答
通过工具和循环约束后与用户问题一起写入。

## 学习资产

| 表 | 首次迁移 | 职责 | 关键约束 |
|---|---|---|---|
| `question_ai_asset` | V5 | 题目、资产类型和生成内容缓存 | 题目与资产类型形成缓存键 |
| `ai_asset_feedback` | V6 | 用户对资产的反馈 | 同一用户对同一资产的当前反馈受约束 |
| `ai_asset_view` | V17 | 资产实际展示给用户的查看事件 | 只在真实展示后记录 |

生成请求不等于查看事件。学习效果分析以 `ai_asset_view` 表示用户确实看到资产。

## 变式训练

| 表 | 首次迁移 | 职责 | 关键约束 |
|---|---|---|---|
| `ai_variant_training` | V18，V19 扩展 | 一次变式训练的开始、完成和关联题目 | 开始操作幂等；完成状态不可随意回退 |
| `ai_variant_question` | V19，V87 扩展 | 结构化变式题、私有答案、首次判分和发布审查 | 首次判分锁定；难度限定 1–5；审查状态只能单向完成 |

V87 为结构校验后的变式题增加 `PENDING`、`APPROVED`、`REJECTED` 审查状态、审查人/时间/说明和唯一的
正式题目引用。批准与正式题目创建在同一事务完成；驳回不创建题目，已完成审查不能重复改写。

## 观察性学习效果

学习效果不单独保存一个结论字段，而是组合：

1. `ai_asset_view` 的真实查看；
2. `ai_variant_training` 与 `ai_variant_question` 的训练和首次判分；
3. `practice_record` 的阅读前后真实作答；
4. 去重学习者覆盖和样本量门槛。

样本不足时只能返回 `INSUFFICIENT_DATA`。该模型支持观察性关联，不支持因果推断。

## 数据保留

- 调用日志和审计日志按运营与调试需要保留，不写入秘密值。
- Tutor Agent 对话正文按用户功能数据处理，删除策略必须同时清理运行与消息，不能把正文复制进调用审计。
- 用户生成内容和反馈的删除策略必须同时考虑个人数据与学习统计一致性。
- 已固化的 Token、成本、判分和审计事实不因配置变化回算。
