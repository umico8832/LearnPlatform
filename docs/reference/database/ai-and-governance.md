# AI 与治理数据

## 调用与配额

| 表 | 首次迁移 | 职责 | 关键约束 |
|---|---|---|---|
| `ai_call_log` | V1，后续迁移扩展 | 功能、模型、Token、成本、trace 和指纹 | 不保存 API Key；成本按调用时配置固化 |
| `ai_quota_audit_log` | V12 | 用户配额调整审计 | 保存操作者、前后值和原因 |
| `ai_usage_alert` | V14 | 用量异常和运营提醒 | 确认操作保留确认人和时间 |

调用准入在独立短事务内锁定用户并插入 `RUNNING` 日志，结束后更新原记录。`call_id` 唯一，
`run_id` 对普通调用为空；`call_kind` 区分聊天与 Embedding。`requested_model` 保存请求模型，
`model` 使用上游返回名称（若提供），价格在准入时快照。`finish_reason` 与 `outcome` 区分生成结束与处理结果。

`status` 保留旧的成功标识，未确认记录依靠 `outcome=RUNNING` 识别。配额计入全部已登记调用，
完成日志列表、成功率和运营报告排除未确认记录。旧日志的新增追踪字段保持空值，不编造历史元数据。

上游失败或后端结构校验失败仍可能有真实用量；缺失字段保持空值。进程退出或审计更新失败时，
已提交登记不随领域事务回滚；需核对上游及运行记录后处理未确认状态，不自动返还配额。

Embedding 每个批次记录 `call_kind=EMBEDDING`，只按实际输入用量计费；输出 Token 与结束原因保持为空。
请求指纹覆盖输入文本，模型配置指纹覆盖模型、维度、端点、超时与价格，不包含输入文本或凭据。

## 版本化知识内容

| 表 | 首次迁移 | 职责 | 关键约束 |
|---|---|---|---|
| `knowledge_content_bundle` | V96 | 课程内容键、版本、清单哈希、来源修订、导入者和平台审核状态 | `(course_key, bundle_version)` 唯一；版本内容不可覆盖 |
| `knowledge_content_chunk` | V96 | 版本下的片段正文、稳定 ID、知识点、哈希与来源元数据 | `(bundle_id, chunk_key)` 唯一；整包与片段同事务导入 |
| `knowledge_content_index` | V97 | 向量配置指纹、维度、集合、端点哈希、任务租约和索引状态 | `(bundle_id, index_key)` 唯一；run_key 防止旧任务更新新任务状态 |

`source_quality_status` 保留来源审查状态，`review_status` 为独立平台状态，导入固定为 `PENDING`。
快照属于课程内容库，按稳定内容键关联课程，不包含用户私有资料，也不自动写入现有教学内容表。
并发导入通过版本唯一索引和行锁串行化，事务采用 READ COMMITTED，避免等待锁后继续读取旧片段快照。
数据库导入不代表向量索引已创建或内容已向学习者开放。V97 增加平台审核者、时间和说明，审核与来源质量分离。
索引状态为 `INDEXING`、`READY`、`FAILED`、`DELETED`、`PURGED`；120 秒租约支持中断恢复，
续租、完成和失败更新绑定当前运行标识。只有完整片段数且版本仍 `REVIEWED` 时允许 `READY`。
撤回将非 `PURGED` 索引标记为 `DELETED`，保留未到期写入租约；删除确认后标为 `PURGED`，
后续重试只处理仍未清理的记录。端点哈希和集合名用于恢复原外部存储的清理范围。

## Tutor Agent 运行

| 表 | 首次迁移 | 职责 | 关键约束 |
|---|---|---|---|
| `tutor_agent_run` | V95 | 运行归属、状态和下一消息序号 | `run_key` 唯一；每次执行通过独立标识和租约避免并发推进 |
| `tutor_agent_message` | V95 | 成功轮次的用户可见问题与回答 | `(run_id, sequence_no)` 唯一；内部工具消息不持久化 |

一次用户提问中的多次 `ai_call_log` 共享 `tutor_agent_run.run_key` 对应的 `run_id`，但各自独立准入、计费和
记录终止原因。调用审计仍不保存 Prompt 或响应正文；可恢复对话正文属于独立的用户功能数据，只在最终回答
通过工具和循环约束后与用户问题一起写入。

V99 增加可空的 `execution_key` 和 `lease_until`。每次创建或继续提问领取一个新的执行标识，
租约由数据库时钟计算，固定为 10 分钟；到期后用户可以重新领取同一运行。成功更新须同时匹配执行标识、
下一消息序号和有效租约，状态推进与两条消息写入同事务，写入失败整轮回滚。失败更新也绑定执行标识，
旧请求不能覆盖新请求。领取使用 READ COMMITTED，取得行锁后读取最新消息序号与历史。
存量记录保持空租约，不伪造历史执行；旧 RUNNING 可重新领取。执行标识不作为公开 DTO 返回，
过期恢复不自动重发模型请求或返还已消耗配额。

V100 在 `tutor_agent_message` 增加可空 JSON 字段 `actions_json`，存量消息的空值按无动作读取。
存放服务端确认的 `CHECK` 展示动作与 `HINT` 提示等级（1–3），与 ASSISTANT 正文、用户问题及运行状态
在同一事务中提交。每种动作单轮最多一个，CHECK 与 HINT 可同时存在；旧 CHECK JSON 不需要 level 字段。
重复工具请求在单轮内去重；失败、过期执行和无效动作不能单独留下可操作消息。
动作不包含答案、判分或客户端目标标识，检查结果仍以 `tutor_session` 的首次事实为准。

## 变式训练

| 表 | 首次迁移 | 职责 | 关键约束 |
|---|---|---|---|
| `ai_variant_training` | V18，V19 扩展 | 一次变式训练的开始、完成和关联题目 | 开始操作幂等；完成状态不可随意回退 |
| `ai_variant_question` | V19，V87 扩展 | 结构化变式题、私有答案、首次判分和发布审查 | 首次判分锁定；难度限定 1–5；审查状态只能单向完成 |

V87 为结构校验后的变式题增加 `PENDING`、`APPROVED`、`REJECTED` 审查状态、审查人/时间/说明和唯一的
正式题目引用。批准与正式题目创建在同一事务完成；驳回不创建题目，已完成审查不能重复改写。

## 观察性学习效果

学习效果不单独保存一个结论字段，而是组合：

1. `ai_asset_view` 的真实查看；
2. `ai_variant_training` 与 `ai_variant_question` 的训练和首次判分；
3. `practice_record` 的阅读前后真实作答；
4. 去重学习者覆盖和样本量门槛。

样本不足时只能返回 `INSUFFICIENT_DATA`。该模型支持观察性关联，不支持因果推断。

## 数据保留

- 调用日志和审计日志按运营与调试需要保留，不写入秘密值。
- Tutor Agent 对话正文按用户功能数据处理，删除策略必须同时清理运行与消息，不能把正文复制进调用审计。
- 用户生成内容和反馈的删除策略必须同时考虑个人数据与学习统计一致性。
- 已固化的 Token、成本、判分和审计事实不因配置变化回算。
