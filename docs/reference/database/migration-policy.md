# Flyway 迁移策略

## 版本基线

| 版本 | 主要变化 |
|---|---|
| V1 | 核心用户、课程、题库、练习、考试、收藏、AI 日志和学习计划 |
| V2 | `exam_answer` 唯一约束 |
| V3 | 幂等补齐 `learning_plan` |
| V4 | 评论与点赞 |
| V5–V6 | AI 学习资产与反馈 |
| V7–V8 | 投稿、来源追踪和复审 |
| V9 | 间隔重复调度 |
| V10–V14 | AI 成本、配额、trace、指纹和提醒 |
| V15–V16 | 纠错报告和题目版本 |
| V17–V19 | 资产查看、变式训练和结构化变式判分 |

## 编写规则

1. 已进入共享历史的迁移文件不可修改或重排。
2. 新迁移使用下一个连续版本，并采用可读名称。
3. 对存量表增加非空字段时，先设计默认值和存量数据回填。
4. 唯一约束上线前先确认存量数据没有冲突。
5. 迁移必须能在空数据库从 V1 连续执行，也必须能从上一个版本升级。
6. Java 实体、Mapper、DTO、测试和数据库文档在同一变更中同步。

## 外键策略

项目主要使用逻辑外键，原因是本地学习项目需要较低的迁移和演示环境维护成本。代价是删除保护、引用校验和跨表一致性必须在 Service 事务与集成测试中明确实现。

数据库唯一索引仍用于保护不能只依赖应用校验的并发不变量。

## 验证

默认验证：

```bash
cd backend
mvn clean verify
```

真实 MySQL 迁移和约束验证：

```bash
cd backend
mvn test -Dgroups=integration
```

Testcontainers 测试应覆盖空库迁移、关键唯一约束、幂等操作和事务边界。具体命令和当前测试分层见[测试策略](../../development/testing.md)。
