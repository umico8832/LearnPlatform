# 学习激励 API

所有接口要求当前登录用户，只表达可追溯的学习投入，不表达掌握度或学习效果。

| 接口 | 说明 |
|---|---|
| `GET /api/gamification/summary` | 等级、经验、连续自然日、每日目标与连击概况 |
| `GET /api/gamification/achievements` | 已解锁和未解锁成就及真实进度 |
| `POST /api/gamification/daily-goal` | 设置 `{ "dailyGoal": 1..200 }` |
| `GET /api/gamification/heatmap` | 最长一年、仅返回有投入的日期 |
| `POST /api/gamification/backfill` | 幂等补算当前用户历史课程学习事件 |

`summary` 的 `version` 和 `lastEventId` 是单调水位；客户端只应用不早于当前水位的概况，防止迟到的提交响应回退显示。`zoneId` 固定为 `Asia/Shanghai`。

`PracticeResultVO.reward` 是该次即时判分事实的奖励反馈，包含 `eventId`、`awardedXp`、`reason`、升级、`currentCombo`、`maxCombo`、新成就和同步 `summary`。同一课程内同一学习对象同一自然日只按首个已判分事件记入经验、目标、连续日和连击：若首答错误，随后答对仍返回 `DUPLICATE_QUESTION_SAME_DAY` 与零经验。考试作答过程不返回奖励；结果页只能展示该次最终提交的聚合奖励。概况、成就和热力读取会自动初始化历史奖励，不要求客户端先请求补算。

热力日 `answeredCount` 与每日目标使用同一口径，为按课程、对象类型、对象 ID 和自然日去重且实际获得经验的作答对象数，`earnedXp` 为当天经验总和；零值日期由客户端按查询范围补齐。
热力查询必须传入 `from`、`to`，格式为 `YYYY-MM-DD`，两端日期均包含；结束日期不得早于开始日期，日期差最多 366 天。

## 奖励口径

仅个人课程库中已写入 `course_learning_event` 的服务端判分事实进入奖励；浏览、AI 辅助、未判分与库外题目不发奖。首个已判分事实答对为 10 经验、答错为 2；复习答对为 14。首次错误后的同日重答仍保存真实业务结果，经验为 0。等级阈值为 `25 × level² + 25 × level − 50`，Lv.2 / Lv.3 / Lv.4 分别从 100 / 250 / 450 经验开始。

连续答对跨即时学习入口累计，只考虑当日对象首次获得经验的已判分事件，错误归零；考试事实不影响该序列。组总结显示本组期间观察到的最高服务端连击，不宣称组内独立连击。连续学习使用已获经验的自然日，今天尚未作答且昨天已学习时仍保留连续天数。

12 项成就覆盖首答、累计作答 10 / 50 / 100、累计正确 10 / 50、复习 10、连续学习 3 / 7 / 30 天、首个 Tutor 检查与首个阶段测评作答。重复、防刷事件不推进进度；历史最高连续天数用于解锁，当前连续天数过期不撤回历史成就。测评成就的事实是首次测评作答。

即时反馈字段覆盖练习、复习、试卷学习、AI 变式训练与 Tutor 理解检查。`reward` 可为空；复习响应的 `correct` 为本次实际判分（未判分时为空），客户端不得从复习间隔推断对错。考试聚合契约见[考试 API](exams.md)。
