# ADR-0006：用户学习端与管理系统采用独立前端应用目标

- 状态：Accepted
- 记录日期：2026-08-02
- 类型：前端与部署架构

## 背景

当前 Vue SPA 同时承载普通用户和管理员页面。随着产品转向课程库、AI 教学、试卷学习
和课程总览，用户端需要连续、沉浸的学习交互；管理端则围绕课程、试卷、题目、课件、
审查、用户和 AI 运营执行表格、审核与批量操作。继续扩展同一个路由和布局会增加导航、
权限、发布和回归耦合。

项目仍由单人维护，现有 Spring Boot 后端、Vue 管理页面、账号和数据库已经可用。为了
形式上的分离同时拆后端、数据库、仓库或重写技术栈，会增加成本而不改善权限边界。

## 决策

目标架构采用两个独立 Vue 前端应用：

```text
用户学习端
├── 课程商店与个人课程库
├── 课程总览
├── AI 教学
├── 试卷学习、考试与复盘
└── 错题、复习和学习概况

管理系统
├── 考试目录、课程与知识点
├── 官方试卷、题目与版本
├── AI 生成、审查与教学增强
├── 互动课件和用户内容治理
└── 用户、角色、配额、成本与运行状态
```

两端继续使用 Vue 3、TypeScript 和现有组件与设计变量，共用 Spring Boot 后端、账号
体系、业务数据和可复用 API 类型。管理员前端独立不构成安全边界，所有管理接口继续
由后端进行身份、角色和资源权限校验。

当前单 SPA 是迁移起点，不在文档更新时声明为已经拆分。迁移优先复用现有管理页面，
不为前端分离引入 React 重写、微前端、第二套后端、第二套数据库或多仓库同步。

Web 是当前主开发端。AiStu 桌面端在课程、会话、题目和学习状态协议稳定后再复用核心
能力；当前阶段不要求同步实现两端。

## 部署选择

首选同域部署以降低会话、Cookie、CORS 和本地开发复杂度：

```text
/          用户学习端
/admin/    管理系统
/api/      统一后端
```

独立子域是未来可选部署方式，不作为首次拆分的前置条件。

## 影响

- 新的用户学习信息架构不再受现有管理导航和布局约束。
- 管理页面迁移需要独立入口、Router、布局、构建和关键权限回归。
- 前端共享范围优先限制为 API 类型、请求客户端、通用工具和稳定设计变量，避免创建难以演进的全量共享组件层。
- 当前前端架构文档继续描述真实单 SPA，拆分实现完成后再更新为当前结构。
- 管理员仍可使用普通学习端，普通用户不能因为知道管理端地址而获得管理权限。

## 未决定事项

- 两个应用在仓库中的最终目录和 workspace 配置；
- JWT 向更适合同域多应用的会话机制演进与否；
- 管理系统独立构建和部署的具体 CI 流程；
- 现有页面的迁移批次。

这些事项在前端分离任务开始前结合真实代码设计。
