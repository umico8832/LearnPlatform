# ADR-0015：AI 执行使用有界准入，默认固定平台线程

- 状态：Accepted
- 记录日期：2026-10-23
- 类型：并发与资源治理

## 背景

原 AI 执行器使用2个核心线程和50个排队位置。题目追问包含完整生成与独立判断，排队会占用请求和本题次数，并把等待放大到模型调用之外。线程类型与准入容量是两个不同决策，不能用无限虚拟线程替代容量治理。

## 决策

使用明确的 AI 执行器，默认8个平台线程；准入许可覆盖准备和实际执行，获取失败立即返回容量拒绝。运行中取消向工作线程传递中断，许可由最终完成路径释放，避免上游尚未退出便接收替代工作。准备失败、未执行拒绝、超时、异常和关机均有对应清理；未执行的容量拒绝保留审计且恢复本题次数。真实上游调用的用量审计继续保留。

保留相同准入上限的虚拟线程模式作为配置选项。默认平台线程来自同镜像、同夹具、同mock延迟、同8许可的单轮A/B：8 VU各24次成功，平台成功P95为2508.90ms、吞吐3.190次/秒，虚拟为2550.84ms、3.172次/秒。该样本没有支持虚拟线程优势，8个固定线程足够且资源关系直观。结果限于本机模拟上游，不能推断虚拟线程普遍更慢或生产容量。

## 取舍与边界

过载时明确拒绝让调用方决定何时重试，代价是突发请求无法依赖长队最终执行。64 VU、每VU立即尝试3次时两模式均24/192成功；平台拒绝P95为83.44ms，最大97.58ms。此负载中被拒用户很快退出，不是自然用户重试模型，也不能把更短的全场耗时称为模型提速。

准入是单进程容量限制，不能声称跨实例全局限流。安全检查、每日配额和本题次数仍是独立业务边界；完整契约见[题目导师API](../../reference/api/question-tutor.md)，AI调用治理见[AI架构](../ai-system.md)。
