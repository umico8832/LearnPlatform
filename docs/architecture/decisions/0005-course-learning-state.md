# ADR-0005：AI 教学与试卷学习共享课程学习状态

- 状态：Accepted
- 记录日期：2026-08-02
- 类型：产品与数据架构

## 背景

项目原有能力分别围绕课程、题库、练习、错题、复习、考试和 AI 学习资产构建。转型为
AI 课程学习平台后，用户可以从 AI 教学或试卷学习进入同一门课程。如果两个入口各自
保存进度、错误和后续任务，课程总览会出现互相冲突的状态，AI 也无法可靠继续学习。

同时，用户可选的知识点自评、浏览记录、有效学习事件和真实作答具有不同证据含义，
不能压缩成一个缺少来源的“掌握度”字段。

## 决策

课程长期学习过程是产品中心。AI 教学和试卷学习是两个并列入口，但必须通过结构化
学习事件更新同一套课程学习状态。

课程学习状态至少需要表达以下职责，具体表结构和 API 在实现任务中确定：

```text
CourseLearningState
├── 当前教学位置与未完成内容
├── 已接触课程、章节和知识点
├── 题目作答与测评记录
├── 错题和对话误解
├── 课件互动与理解检查
├── 待复习任务和真实重试
└── 用户自评与系统学习证据的分离引用
```

系统根据未完成教学、到期复习、重要错误和默认课程顺序形成候选教学目标，AI负责
具体讲解、问题、课件和后续教学选择。AI 不能依赖未结构化的完整聊天历史独自维护
课程进度。

官方原题、用户私有资料和 AI 生成题保留来源域；审查 Agent 通过的生成题在业务流程
中视为正确的正式学习内容，可以产生练习、错题、复习和测评事件。内容来源差异不允许
形成第二套用户学习状态。

## 不变量

- 添加课程、浏览目录和填写自评不直接表示掌握。
- AI 教学和试卷学习不能各自维护一份课程进度。
- 错题、误解、复习和测评保留来源与历史，不用最新结果覆盖先前学习事实。
- 课程总览从统一业务状态读取，不在前端临时拼接另一套权威结果。
- 客观题判分、权限和持久化事实仍由后端负责。
- 用户私有资料、平台官方内容和 AI 生成内容不因共享学习状态而混成同一内容域。

## 影响

- 新课程总览、Tutor、试卷学习和上传资料功能必须先定义学习事件，再修改状态。
- 现有练习、错题、复习、考试和 AI 事件需要盘点并逐步映射，而不是一次性重写。
- 画像只能从可解释的学习事件聚合，在数据不足时展示客观记录。
- 第一阶段用 408 数据结构和一张结构化真题验证状态模型，再扩展课程和内容规模。

## 未决定事项

- 数据库表、事件版本和幂等键的精确设计；
- 课程默认教学顺序与复习优先级算法；
- 用户上传资料的首批格式和解析契约；
- 课程总览的具体进度表达。

这些事项在对应实现开始前进入 API、数据库或专项架构设计，不在本 ADR 中提前声明为
已实现。
