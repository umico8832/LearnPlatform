# ADR-0011：学习端重做为“会动的课本”视觉与弹簧动效基线

- 状态：Accepted
- 记录日期：2026-10-10
- 类型：前端架构

## 背景

[ADR-0010](0010-quiet-digital-textbook-motion.md) 的暖纸底色、低饱和蓝和短促 Vue/CSS 过渡保证了一致与克制，
但学习端整体显得平淡，无法支撑以“看懂过程”为核心的教学体验；在独立分支上尝试的 One Shape 黑白风格也未被采用。

项目当前以“一道题从错到懂”为演示主线：作答、针对所选错项的讲解、用题目自身数据播放并先预测的可视化、
无提示变式题和后续复习。本地原型已验证框架无关的可视化引擎与弹簧动效能承担这条主线。

## 决策

学习端采用“会动的课本”方向：阅读的地方安静，帮助理解的地方会动。

- 视觉：中性浅灰画布、白色大圆角卡片、系统字体（数字使用圆体）、系统蓝强调色，同时提供浅色与深色。
  颜色只承载固定含义：绿色表示正确，橙色表示需要注意，紫色表示预测或假设，程序变量使用固定身份色。
- 动效：统一使用解析解弹簧，以响应时间与阻尼两个参数描述手感，并维护少量命名预设（布局、指针、弯曲、
  按钮、淡入、镜头）。动画可随时打断并保留速度；CSS 与 WAAPI 动画使用由同一弹簧生成的缓动曲线。
- 程度分三档：轻档用于题干、解析、代码与 Markdown 等阅读区，只做淡入或滑入，阅读时不移动；中档用于控件、
  导航、面板与列表；强档用于可视化课件和关键时刻。面板从触发处展开，新元素从来源位置飞出。
- 可视化：AI 只给出场景描述（结构、数据、停顿与提问位置），确定性模拟器逐步计算状态，播放器和舞台只负责呈现；
  不执行模型生成的代码。
- 依赖：弹簧核心自行维护；手势惯性、跨页面过渡等难点可以引入成熟动效库或原生 View Transitions，
  参数对齐上述预设。
- 迁移：学习端按演示主线逐页重做，新页面从头设计，不以旧页面样式为参照；尚未重做的页面和管理端保持
  ADR-0010 的实现，不做零碎混改。

## 备选方案

- 继续 ADR-0010：一致但缺少表现力，不能体现可视化教学这一核心能力。
- One Shape 黑白风格：已实现一轮，整体体验未被接受，仅作为历史保留在 `feat/one-shape` 分支。
- 全面采用通用动画库驱动所有动效：可视化舞台需要按 id 对比帧、指针重定向和镜头取景等专用行为，
  自行维护的小型弹簧核心更可控；通用库仅用于其擅长的部分。

## 影响与不变量

- `tokens.css`、`motion.css` 与 Element Plus 映射将在迁移中替换为新基线；完成前两套基线按页面隔离。
- 以下 ADR-0010 不变量继续有效：判分、奖励与掌握的动效只表达后端已返回的结果（可视化步骤与预测反馈由确定性
  模拟器演算，不受此限）；限时考试提交前保持静默，只用轻档且不暗示对错；
  不使用奖励飘字、全屏庆祝、彩纸、连击火焰、成就弹窗或无状态含义的常驻循环。
- 动画不延迟操作、焦点、验证或导航；`prefers-reduced-motion` 下弹簧直接到达终点，保留结果与操作。
- 设计与动效的操作规则由项目 `frontend-design` 与 `interaction-motion` Skill 维护。
