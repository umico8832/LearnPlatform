# ADR-0013：统一纽约业务时间

- 状态：Accepted
- 日期：2026-10-18

## 背景

用户已决定产品采用美国东部时间。原实现混用上海常量、机器默认时间和数据库会话时间，
使每日配额、连续学习和复习日期随部署环境变化。

## 决策

业务时区统一为 `America/New_York`，由共享业务时钟集中提供；所有本地时间和业务自然日显式使用它。
数据库会话使用同一命名时区，不修改 JVM 全局默认时区，以便测试发现环境依赖。
复用考试已有 `Clock` 注入模式与 FSRS 已有 UTC 时间方式；考试增加 UTC 起点，按绝对时间计算时长。
纯日期保留原排期，奖励历史事实保留已发经验，仅重建派生日期与连续日。

不采用固定 UTC 偏移或固定减 12 小时：纽约夏令时切换日有跳时与重复小时。
不把全部历史列改为 UTC，以控制现有无偏移 API 的兼容范围。存储边界见[时间语义](../../reference/database/time-semantics.md)。

## 影响

替代 [ADR-0009](0009-learning-effort-gamification.md) 的上海自然日与机器源时钟约定，其他奖励规则保留。
本地日期时间用于展示和按日分组；考试精确计时依赖 UTC 起点。运行环境需提供 MySQL 命名时区规则。
