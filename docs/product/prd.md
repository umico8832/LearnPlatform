# 产品需求文档（PRD）

## 一、产品概述

### 1.1 产品名称
AI 驱动的题目学习平台 (AI Learning Platform)

### 1.2 产品定位
面向学习者和备考人群的 AI 驱动题目学习平台，保留在线刷题、错题复习、模拟考试、题库管理和学习统计等核心业务，并通过 AI 能力把题目从静态内容升级为可讲解、可交互、可诊断、可推荐、可共建的学习对象。

平台不只提供“答案和解析”，而是围绕一道题形成从作答、判分、错因定位、结构化讲解、变式训练到复习推荐的学习闭环。同时作为可放进简历的中大型全栈 Web 项目，展示前后端分离、数据库设计、权限控制、AI 集成、工程质量和可持续迭代能力。

### 1.3 目标用户
| 用户角色 | 说明 |
|---------|------|
| 普通用户 | 学生、备考者，进行刷题、错题复习、模拟考试 |
| 管理员 | 教师、课程管理者，进行题库管理、试卷管理、用户管理 |

### 1.4 产品目标
1. 提供完整的题库管理和在线刷题体验
2. 自动收集错题并支持智能复习
3. 集成 AI 提供结构化题目讲解、变式题生成、错因诊断和复习计划等能力
4. 提供可视化学习统计，帮助用户了解薄弱环节
5. 支持模拟考试和成绩分析
6. 沉淀题目 AI 学习资产，为后续可视化讲解、学习画像、个性化推荐和题库共建打基础
7. 代码结构清晰，可作为简历项目进行面试讲解

## 三、详细功能需求

### 3.1 用户系统

#### 3.1.1 用户注册
- 输入：用户名、密码、昵称
- 用户名唯一校验
- 密码使用 BCrypt 加密存储
- 注册成功返回 JWT Token

#### 3.1.2 用户登录
- 输入：用户名、密码
- 验证成功返回 JWT Token
- Token 有效期配置化（默认 7 天）

#### 3.1.3 个人信息
- 获取当前登录用户信息
- 修改昵称、头像
- 修改密码（需验证旧密码）

#### 3.1.4 角色权限
- USER：普通用户，可刷题、查看错题、参加考试
- ADMIN：管理员，拥有所有管理端权限

### 3.2 课程与知识点系统

#### 3.2.1 课程管理
- 课程 CRUD（创建、查看、修改、删除）
- 字段：课程名称、描述、封面图、排序、状态
- 管理端可管理所有课程

#### 3.2.2 知识点管理
- 知识点 CRUD
- 支持父子层级结构
- 字段：知识点名称、描述、所属课程、父知识点ID、排序
- 管理端可管理所有知识点

### 3.3 题库系统

#### 3.3.1 题目类型
| 类型 | 说明 |
|------|------|
| SINGLE_CHOICE | 单选题，只有一个正确答案 |
| MULTIPLE_CHOICE | 多选题，多个正确答案 |
| TRUE_FALSE | 判断题，对/错 |
| FILL_BLANK | 填空题（后期） |
| SHORT_ANSWER | 简答题（后期） |

#### 3.3.2 题目属性
- 题干（支持 Markdown）
- 所属课程
- 所属知识点（可多个）
- 难度等级（1-5）
- 标签
- 解析
- 启用/禁用状态
- 创建时间、更新时间

#### 3.3.3 选项管理
- 选项内容
- 选项排序
- 是否为正确答案

### 3.4 刷题系统

#### 3.4.1 练习模式
- **按课程刷题**：选择课程后，在该课程题目中练习
- **按知识点刷题**：选择知识点后，在该知识点题目中练习
- **随机练习**：从题库中随机抽取题目
- **顺序练习**：按题目编号顺序逐题练习

#### 3.4.2 答题与判分
- 用户提交答案
- 系统自动判分（客观题自动判，简答题后期支持 AI 评分）
- 返回判分结果和正确答案
- 展示题目解析

#### 3.4.3 刷题记录
- 记录每次答题：题目ID、用户答案、是否正确、答题时间
- 统计：总刷题数、正确数、正确率

### 3.5 错题本系统

#### 3.5.1 自动收集
- 用户答错的题目自动加入错题本
- 同一题目不重复添加

#### 3.5.2 错题管理
- 查看错题列表，支持按课程、知识点筛选
- 手动移出错题本
- 错题掌握状态：未掌握 / 部分掌握 / 已掌握

#### 3.5.3 错题重练
- 针对错题本中的题目进行重新练习
- 答对后可更新掌握状态

#### 3.5.4 统计
- 高频错题知识点排行
- 错题数量趋势

### 3.6 试卷 / 模拟考试系统

#### 3.6.1 试卷管理（管理端）
- 创建试卷：填写试卷名称、时长、总分、描述
- **手动选题**：从题库中手动选择题目组成试卷
- **随机组卷**：指定课程/知识点/难度/题型/数量，系统自动随机抽题
- 试卷状态：草稿 / 已发布

#### 3.6.2 考试（用户端）
- 选择试卷开始考试
- 倒计时
- 逐题作答或全部作答后提交
- 超时自动提交

#### 3.6.3 考试结果
- 总分、得分
- 每题答题详情（用户答案、正确答案、是否正确、解析）
- 错题分析：薄弱知识点

### 3.7 AI 辅助学习系统

AI 辅助学习系统的长期方向见 [AI 学习平台战略](ai-learning-platform-strategy.md)。PRD 只定义产品层面的能力边界，不把长期功能清单逐项塞入本文档。

#### 3.7.1 AI 功能分层
| 功能 | 说明 | 优先级 |
|------|------|--------|
| AI 题目学习资产 | 围绕单题生成结构化讲解、小白版解析、步骤拆解、错误选项分析、常见误区和变式训练闭环；新变式题只在服务端保存答案，用户首次提交后真实判分并锁定结果，旧 Markdown 缓存兼容显式完成；管理端按真实首次判分展示 1-5 难度样本结构，不用生成次数或按钮冒充正确性 | P0 |
| AI 错因诊断 | 用户答错后识别可能错因，解释错误选项诱因，并沉淀常见误区 | P1 |
| AI 可视化交互讲解 | 将算法、代码执行、SQL、数据结构等过程转为可渲染的步骤数据 | P1 |
| AI 学习画像与推荐 | 根据答题记录、错题、解析使用和变式完成情况，生成学习建议和推荐题目 | P1/P2 |
| AI 题库生产辅助 | 辅助管理员或投稿用户做题目规范化、质检、知识点标注、难度评估和重复检测 | P2 |
| AI 内容治理与管理 | 支持资产缓存、版本记录、人工确认、调用成本统计、Prompt/模型配置和内容来源治理 | P3 |

#### 3.7.2 AI 接入设计
- 统一 AI Provider 抽象层
- 支持配置：API Base URL、API Key、模型名称
- 通过环境变量注入，不硬编码
- 非流式调用（第一版）
- 调用失败时提供友好提示
- AI 功能可整体关闭（未配置 Key 时降级）
- 记录 AI 调用日志（后期）
- 题目 AI 学习资产应优先缓存和复用，避免同一题反复调用造成成本浪费和结果漂移
- 关键内容发布、答案修改、题目入库和投稿审核不应由 AI 自动完成，必须保留管理员确认机制

### 3.8 后台管理系统

#### 3.8.1 功能
- 用户管理：查看用户列表、修改角色、启用/禁用
- 课程管理：课程 CRUD
- 知识点管理：知识点 CRUD
- 题目管理：题目 CRUD、启用/禁用
- 试卷管理：试卷 CRUD、组卷
- 数据统计：题库数量、用户数量、刷题统计

### 3.9 数据统计

#### 3.9.1 用户端统计面板
- 总刷题数
- 正确率
- 错题数量
- 最近 7 天学习趋势图
- 知识点掌握雷达图

#### 3.9.2 管理端数据总览
- 总用户数
- 总题目数
- 总试卷数
- 今日活跃用户
- 各课程题目分布图
- AI 学习资产效果观察：记录真实查看行为，对比同题阅读后作答与基线正确率；同时排除原题重答，在 30 天窗口内观察共享知识点的跨题作答迁移，并按结构化变式首次判分展示难度样本覆盖；同题、跨题、资产类型和难度观察均同时要求最低作答量与去重学习者覆盖，避免少数高频用户主导结论；多资产暴露样本允许重叠，不据此自动排名或推荐；所有指标明确区分观察性关联与因果结论

## 四、非功能需求

### 4.1 安全性
- JWT 鉴权，Token 过期机制
- 密码 BCrypt 加密
- 敏感信息通过环境变量配置
- API Key 不写入代码和 Git
- 管理端接口权限校验

### 4.2 性能
- 首页加载 < 3s
- 接口响应 < 500ms（不含 AI 调用）
- AI 接口超时设置 30s

### 4.3 可用性
- 响应式布局（PC 优先）
- 清晰的错误提示
- 加载状态展示

### 4.4 可维护性
- 前后端分离
- RESTful 接口规范
- 统一响应结构
- 全局异常处理
- 代码注释和文档

### 4.5 部署
- Docker + Docker Compose 一键启动
- 环境变量配置
- .env.example 示例

## 五、接口规范

### 5.1 统一响应结构
```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 5.2 错误码定义
| code | 说明 |
|------|------|
| 0 | 成功 |
| 1001 | 参数校验失败 |
| 1002 | 未登录 |
| 1003 | 无权限 |
| 1004 | 资源不存在 |
| 1005 | 业务异常 |
| 5000 | 系统异常 |

### 5.3 接口风格
- RESTful
- 普通用户接口前缀：`/api`
- 管理端接口前缀：`/api/admin`
- 认证方式：`Authorization: Bearer <token>`
