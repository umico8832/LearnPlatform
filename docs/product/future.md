# 后续扩展方向

本文档只保存尚未完成的候选方向和进入条件。当前阶段、下一步和最新验证以
[项目状态](../project/status.md)为准，已完成阶段见[产品路线图](roadmap.md)。

## 排期边界

当前处于维护阶段，以下均为尚未承诺的候选方向，不自动授权功能扩展。
产品定位与 AI 教学职责见[PRD](prd.md)，已完成能力见[项目状态](../project/status.md)。

## 近期候选

### 课程学习事实

- 课程总览按知识点聚合课程学习事件、错题、到期复习和测评逐题快照，提供作答数、正确数、错题数与
  到期复习数，并联动既有入口；只展示事实，不推断掌握度、趋势或个性化结论。
- 测评题型/难度筛选、更多知识点深链等增强，仅在真实使用需要时进入。

### 工程演进

- Prompt 注册与固定回归样例：Tutor 编排具备代表性样本后，再评估集中治理的收益。
- 依赖与类型问题按实际检查结果进入维护，不保留未经复核的漏洞或 lint 数字作为长期待办。

## 中期候选

### 资料解析与内容审查

- 扫描件 OCR、复杂公式、图片题与复杂版式识别，以固定样本集的准确率和复核成本决定进入条件。
- 自动审查 Agent：先定义评测样本、错误阻断与发布责任，再评估自动化范围；不得把产品目标视为绕过
  当前管理员发布权限的依据。

### 内容与课程扩张

- 在 408 数据结构闭环稳定后扩展计算机组成原理、操作系统和计算机网络。
- 建立官方试卷来源、版本、结构化和勘误流程。
- 根据真实教学需求增加互动课件，不追求每题或每知识点都有课件。

### 学习画像

- 继续积累教学、原题、生成题、错题、复习和延迟作答事件。
- 数据充分后再形成可解释画像，不把浏览、自评或单次作答直接判定为掌握。
- Phase 22 已有观察性统计继续保持非因果表达。

### 推荐增强

- 在题库规模、真实使用量和规则推荐效果证明必要后，评估向量相似度。
- 向量能力只增强候选召回，不替代权限、题型、课程和难度过滤。
- 上线前需要固定离线评测集和可解释回退策略。

## 长期候选

- AiStu 桌面端复用稳定的课程、会话、题目和学习状态协议。
- 更完整的离线课程、桌面通知、本地 Provider 和多窗口课件能力。
- 班级、教师、作业和多租户。
- 移动端或小程序。
- 语音交互。
- 多模型路由和更复杂的个性化模型。

这些方向需要核心 Web 闭环、真实需求、数据规模和运维能力同时成立。它们不是默认
并行路线，也不应为了展示提前堆叠。

## 排期原则

1. 双入口闭环的可靠性和真实使用反馈优先于新增入口与内容。
2. 先验证单课程、单试卷和少量课件，再扩大规模。
3. 能复用现有模块的能力，不创建第二套实现。
4. 高成本功能必须同时设计配额、降级和可观测性。
5. 新能力完成设计后，再更新 API、数据库和专项架构文档。
