# 后续扩展方向

本文档只保存尚未完成的候选方向和进入条件。当前阶段、下一步和最新验证以
[项目状态](../project/status.md)为准，已完成阶段见[产品路线图](roadmap.md)。

## 当前判断

平台已有鉴权、题库、真实判分、错题、复习、考试、AI 学习资产、内容治理和运营
基础。当前瓶颈不是继续增加孤立功能，而是让这些能力与 AI 教学共同更新一套课程
学习状态。

近期先用单课程和单试卷验证双入口闭环，不同时扩张格式、课程、画像、桌面端和复杂
推荐。

## 近期候选

### 课程学习平台基础

- 定义课程学习状态、结构化学习事件和跨入口一致性规则。
- 用 408 数据结构建立课程库、课程总览和默认教学顺序。
- 让 AI 教学读取未完成内容、到期复习、重要错误和课程顺序后组织本次学习。
- 将现有错题、复习、练习、考试和 AI 事件逐步接入统一状态。

### 真题学习

- 先接入一张结构化权威真题，保留试卷、大题、小题和子问题结构。
- 跑通学习模式、考试模式和复盘模式的最小差异。
- 让原题作答、AI 辅导、互动课件和后续练习回到同一课程记录。

### 前端应用分离

- 建立独立用户学习端和管理系统的目标目录、构建与路由边界。
- 先迁移现有管理页面，不为分离重写后端、数据库或成熟页面。
- 保持同域部署作为首选，真实需要出现后再评估独立子域。

### 工程债务

| 事项 | 当前状态 | 进入条件 |
|---|---|---|
| 前端显式 `any` | ESLint 无阻断错误，仍有存量警告 | 修改相关模块时逐步收紧 |
| ECharts 依赖公告 | 存在需要跨主版本处理的中危公告 | 配合图表页面回归单独升级 |
| Prompt 注册与评测 | Prompt 仍分布在多个 Service | Tutor 编排进入固定回归样例后统一 |

## 中期候选

### 用户资料导入

- 支持文本型 PDF、DOCX、Markdown 或现有结构化格式中的有限集合。
- 自动拆解后先让用户确认试卷结构，再进入正式学习。
- 原文件、解析结构、教学增强和用户学习状态分层保存。
- 扫描件 OCR、复杂公式和图片题在固定样本集达到可接受准确率后进入。

### 内容与课程扩张

- 在 408 数据结构闭环稳定后扩展计算机组成原理、操作系统和计算机网络。
- 建立官方试卷来源、版本、结构化和勘误流程。
- 根据真实教学需求增加互动课件，不追求每题或每知识点都有课件。

### 学习画像

- 继续积累教学、原题、生成题、错题、复习和延迟作答事件。
- 数据充分后再形成可解释画像，不把浏览、自评或单次作答直接判定为掌握。
- Phase 22 已有观察性统计继续保持非因果表达。

### 推荐增强

- 在题库规模、真实使用量和规则推荐效果证明必要后，评估向量相似度。
- 向量能力只增强候选召回，不替代权限、题型、课程和难度过滤。
- 上线前需要固定离线评测集和可解释回退策略。

## 长期候选

- AiStu 桌面端复用稳定的课程、会话、题目和学习状态协议。
- 更完整的离线课程、桌面通知、本地 Provider 和多窗口课件能力。
- 班级、教师、作业和多租户。
- 移动端或小程序。
- 语音交互。
- 多模型路由和更复杂的个性化模型。

这些方向需要核心 Web 闭环、真实需求、数据规模和运维能力同时成立。它们不是默认
并行路线，也不应为了展示提前堆叠。

## 排期原则

1. 先完成课程学习状态，再扩张入口和内容。
2. 先验证单课程、单试卷和少量课件，再扩大规模。
3. 能复用现有模块的能力，不创建第二套实现。
4. 高成本功能必须同时设计配额、降级和可观测性。
5. 新能力完成设计后，再更新 API、数据库和专项架构文档。
